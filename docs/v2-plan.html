Status tab: how it knows

Live check (in the page)

The mcp capability calls one harmless read per connector: Notion search, NinjaTrader my_portfolio, Google Calendar list. Shows Connected, Not connected or Needs sign-in. The page's manifest names only read tools, so it can never place an order.

Heartbeat (from the morning run)

The Healthchecks.io / Gatus "push" pattern: each run writes status/last_run with the time, ok/failed per source and doctor.py --json. The page turns amber when a run is overdue.

  4. Hello setup Artifact ~3 h: intro screen, answers to db, CLAUDE.md SETUP reads them. Done when a blind test runs setup with no copy-paste.
  5. Blind test ~1 h: same two-part test as today, plus the phone view.

Risks and open questions

  • Who publishes: her own Claude should, so she owns it and her connectors answer. Jason sees her data only if she shares it.
  • db size cap isn't stated in the type definitions. If 90 days don't fit one doc, split into trades/<month>.
  • Custom connectors via mcp (NinjaTrader) are unconfirmed. Fallback: its row reports from the heartbeat only.
  • Scheduled-task writes: if a scheduled run can't call ArtifactData, it republishes the page with the data embedded instead.
  • Offline: the folder keeps dashboard.html + data.js, so a local copy always works.
